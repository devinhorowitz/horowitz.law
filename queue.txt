# Georgia Appellate Watch -- case queue (inbox)
#
# Add a case to the feed by pasting its CourtListener opinion URL on its own line
# below and committing this file. A push to queue.txt runs the case through the
# funnel and opens a pull request for your review; nothing goes live until you
# merge it. You can also run it by hand from Actions > "Georgia Appellate Watch
# queue" (with "resolve only" first to check what a line resolves to).
#
# One case per line. Accepted forms:
#   https://www.courtlistener.com/opinion/10862301/state-farm-v-.../   (paste the URL)
#   10862301                                                            (bare cluster id)
#   10862301:gactapp                                                    (cluster:court, if the
#                                                                        court will not auto-derive;
#                                                                        court in ga|gactapp|ca11|scotus)
#
# Add a trailing "!" to force a case past the relevance gate (it is still subject
# to your PR review):
#   10862301 !
#
# Anything after "#" is a comment. Each case is screened: a case judged out of
# scope is reported in the PR rather than carded (force with "!" to override).
#
# After a run this file is drained automatically: carded, gated-out, declined, and
# already-on-the-site lines are removed and reported in the PR; lines deferred on the
# CourtListener budget stay to retry; unresolved lines are parked here as comments
# with the reason, for you to fix or delete.
#

# THE DRAIN REMOVES THE ENTRY LINE AND NOTHING ELSE. Comments never go with it, wherever they sit.
#
# Learned twice. First from indented continuations trailing a drained id (the Alabama escalations
# from issue #191, cleared 2026-08-23), which at least LOOKED like litter. Then from a note placed
# ABOVE its id on the theory that the drain would "take the whole note with it" -- it did not, and
# the 2026-08-25 drain of the Zoll line left ~25 orphaned lines including that very claim, cleared
# here. A block above an id reads as deliberate, which makes it worse litter than the indented
# kind, not better.
#
# So: keep a queued line's note to a word or two, and put the real reasoning in the commit message
# and PR body, where it is durable and does not need sweeping up afterwards.
