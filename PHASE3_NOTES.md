# Phase 3: distribution · 2026-06-11

Per-area subscriptions, the digest archive, and the instant-alert tier.
Sixteen files, zero model spend, Resend free tier holds. **Zero-config
guarantee:** until you set the one new variable, every email behaves exactly
as it does today — verified by dry run.

## 1. Per-area subscriptions

The model the code anticipated: one Resend **Topic per practice area**, the
existing main Topic staying "everything."

- **/subscribe** grows a "what to receive" fieldset — `everything` (default)
  plus the eight areas, generated by render.py from AREA_LABELS between new
  markers, so the form can never drift from the taxonomy. Ticking an area
  unticks everything and vice versa.
- **The choice survives double opt-in honestly:** the sanitized area CSV rides
  the confirmation link *inside the HMAC* (`email.ts.areas`), so it can't be
  tampered with in transit; links from pre-feature emails still verify
  (`email.ts` shape). The confirm page shows the chosen areas before the
  button.
- **confirm.js** maps choices through `RESEND_AREA_TOPICS` and opts the
  contact into those Topics; anything unmapped falls back to the main Topic —
  a confirmed subscriber can narrow what arrives but never lands on nothing.
- **digest.py** sends the main broadcast exactly as before, then one broadcast
  per area *with content that week*, scoped to that area's Topic — so its
  unsubscribe link leaves only that area. Same date-stamped duplicate-proof
  naming, per-area (`… [premises]`). Dry-run output now prints the per-area
  plan. Verified: `auto: 9 new · premises: 7 · negsec: (unmapped, skipped)`.

### To turn it on (one-time, ~10 min)
1. Resend dashboard → create a Topic per area you want to offer (a subset is
   fine; unmapped checkboxes fall back to the main digest).
2. Build the map: `{"coverage":"top_…","premises":"top_…", …}` (keys = the
   area codes: coverage, badfaith, auto, premises, negsec, expert, procedure,
   damages).
3. Set it in **two places**: Cloudflare Pages env var `RESEND_AREA_TOPICS`
   (confirm.js reads it) and GitHub Actions **Variable** `RESEND_AREA_TOPICS`
   (digest.py reads it; digest.yml now passes it through).

## 2. /digests — the weekly email, week by week

Cadence-proof at the point of signup: every week's digest contents,
**reconstructed from the record** (cards by `first_seen` week, flags by
`treatment_date` week — the same selection digest.py uses), so it needs no
sent-mail log, reaches back before the email existed, and stays
CI-deterministic. 27 week sections render today; the launch-week backfill is
honestly labeled as the big one. Linked from /subscribe's fine print, the
colophon feeds directory, and the 404's `ls`. Guarded by check_site, the CI
idempotency diff, and render-sync's add-paths, like every generated page.

## 3. Instant alert (`scripts/alert.py` + `alert.yml`)

For the decision worth knowing **today**: write `[instant-alert]` anywhere in
an opinions PR's body before merging. On merge, the workflow diffs
opinions.json across the merge (HEAD vs HEAD~1) and announces **exactly the
cards that merge added** — nothing typed twice, nothing announced that didn't
merge. Cards link their permanent /o/ pages. Manual path: Actions → instant
alert → Run workflow with explicit ids (dry-run and draft inputs included).
Rides the digest's plumbing wholesale: same segment, main Topic, per-recipient
unsubscribe, the CAN-SPAM postal gate, and date+id duplicate-proof naming.
Misfire-safe: a flagged PR that added no cards announces nothing.
